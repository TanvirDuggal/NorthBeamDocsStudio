Northbeam Docs Studio — Plan
1. Stack and structure: Use Vue 3 for the UI, Python with Flask for the API, SQLite through Python's sqlite3 for storage, and pytest for tests. Keep frontend/, backend/, and specs/ in one repository.
2. Database: Store editable content, slug, status, draft revision, publication pointer, first publication date, and a version counter in articles. Store numbered immutable copies in article_versions. Persist to a local .db file excluded from Git; never reuse deleted version numbers.
3. API: Provide writer endpoints for create/list/view, draft save, publish/unpublish, and history list/view/restore/delete. Provide separate public list/detail endpoints that read only the referenced published snapshot. Validate input and return clear 404 and 409 errors.
4. Consistency: Use short SQLite write transactions and foreign keys on every connection. Keep publish atomic, enforce same-article snapshot references, block snapshot updates and referenced-snapshot deletion, and use conditional revision checks for save/restore/publish. Increment the revision on each of those operations; serialize competing lifecycle writes.
5. Minimal UI: Build an article list, editor with safe Markdown preview, publication controls, history panel, and public pages. Require saving before publishing local changes; show conflicts without discarding local text. No login or role management.
6. Verification and delivery: Test draft isolation, publish rollback, unpublish, restore, protected deletion, concurrent requests, and restart persistence. Provide short local setup instructions, one test command, and a README explaining the model and a tradeoff. These are planning drafts: adopt them through the actual Spec Kit workflow and commit before implementation; that workflow has not yet been run.
